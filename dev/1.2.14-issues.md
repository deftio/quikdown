## Editor coverage 70% — blockers (strict)

**Misconception:** “We have Playwright, so 70% should be easy.” **False for the current setup.**

### What Playwright already covers (robustness ✅, coverage metric ❌)

| Spec | Exercises | Feeds Jest `coverageThreshold`? |
|------|-----------|----------------------------------|
| `quikdown-editor.spec.js` | Modes, toolbar, undo, basic copy text | **No** |
| `quikdown-fences-e2e.spec.js` | SVG, Mermaid, GeoJSON, STL, MathJax, hljs, copy md/html | **No** |
| `quikdown-copy-paste.spec.js` | contenteditable roundtrip | **No** |
| `quikdown-html-whitelist.spec.js` | allow_unsafe_html in browser | **No** |
| `quikdown-bidirectional.spec.js` | BD in browser | **No** |
| `quikdown-standalone.spec.js` | Standalone bundle smoke | **No** (release only) |

Jest/Istanbul only measures code executed during **`npm test`** (jsdom). Playwright runs in a **separate process** with no coverage merge configured.

### What actually blocks 70% on `dist/quikdown_edit.esm.js`

1. **`quikdown_edit_copy.js` (~1,481 lines, bundled into edit)** — `getRenderedContent()`: canvas rasterization, SVG→PNG, heading bounds, output modes (`default` / `stripped` / `quikdown`). Partially mocked in unit tests; large branches still red (~lines 1583–1842, 1966–2057 in bundle report).

2. **No e2e for `copyRendered`** — `quikdown-fences-e2e.spec.js` header lists rich copy; **Copy E2E** only tests `copy-markdown` and `copy-html` (plain text). **`copy-rendered` / `navigator.clipboard.write` with `ClipboardItem` never exercised in Playwright.**

3. **Async fence renderers** — `renderMermaid`, `renderGeoJSON`, `renderSTL` success/error paths need either (a) heavier jsdom mocks of `window.mermaid` / Leaflet / Three, or (b) instrumented e2e + NYC merge (not set up).

4. **CDN library load callbacks** — `FENCE_LIBRARIES` `afterLoad` / error handlers; e2e hits happy path when network allows; failure branches weak.

5. **Dead weight in bundle** — `emitStyles()` in editor build inflates denominator; consider excluding or not counting (architectural, not test-only).

6. **E2e soft-fail** — even perfect Playwright tests don’t raise the bar if they’re allowed to fail silently on PRs.

### Path to 70% (pick one strategy)

| Strategy | Effort | Gets 70% threshold? | Gets robustness? |
|----------|--------|---------------------|------------------|
| **A. More jsdom unit tests** — mock mermaid/leaflet/three, expand `getRenderedContent` matrix in `quikdown_edit_coverage.test.js` | Medium | **Yes** | Partial |
| **B. Playwright + coverage merge** — instrument dist, run e2e with NYC, merge into Jest report | High | Yes | **Yes** |
| **C. Playwright only, no unit push** | Low | **No** | Yes |

**Recommendation for 1.2.14 quality release:** **A + e2e `copyRendered` tests (C’s robustness half)** → ratchet to 70% in `package.json`. Option B is follow-up infrastructure.

## MCP plan for quikdown

**Status:** Not implemented yet. Scope (1.2.14 vs later) is a **release choice**, not a technical gate.

**Architecture decision:** **One MCP** — single export `quikdown/mcp`, single server, **two tool groups**. Which tools appear in `tools/list` depends on whether the host attached a `QuikdownEditor` instance. Not two packages, not two servers.

---

### What it is

**MCP** is a standard way for an **AI agent** to call **tools**. quikdown ships **one MCP adapter** that exposes quikdown capabilities as tools — parse, bidirectional convert, and (optionally) read/write a live editor buffer.

MCP connects **agent ↔ tools**. It does **not** replace the **human’s editor UI**.

---

### What you get — one server, two tool groups

| Tool group | When available | What the agent can do |
|------------|----------------|------------------------|
| **Headless** | Always (stdio bin or `createMcpServer()`) | Parse MD→HTML, HTML→MD (BD), AST/JSON, stats, version info — on **strings or file paths in tool args** |
| **Editor session** | Only when host passes `editor: QuikdownEditor` | `read_editor`, `write_editor`, `replace_text`, `extract_text`, `get_stats`, `undo`, `redo` — on the **live editor buffer** |

**`tools/list` is dynamic:** headless tools always listed; editor tools listed **only if** an editor instance was bound at server creation. Agents never see editor tools they cannot use.

**`quikdown://meta` resource** reports: quikdown version, which tool groups are active, and short guidance (“editor tools require host with QuikdownEditor”).

---

### What the human sees (depends on host, not on MCP package count)

| Host setup | Human UI | Agent uses |
|------------|----------|------------|
| **Cursor + `quikdown-mcp` in MCP config** (no editor) | Cursor’s file editor | **Headless tools** on repo `.md` files |
| **Your app** with `QuikdownEditor` + `createMcpServer({ editor })` | QuikdownEditor split/preview | **Headless + editor tools** on same session |
| **GitHub Pages try-it only** | Browser editor tab | **Nothing** until you run a local host that binds MCP to that editor |

**Cursor / Claude Code do not become QuikdownEditor** unless you embed the widget yourself. With headless tools only, they use quikdown as **engine** while the IDE stays the editor. With editor bound, the agent drives **your app’s** quikdown pane.

---

### API shape (when built)

**One export:** `quikdown/mcp`  
**Optional bin:** `quikdown-mcp` — stdio, headless tools only (typical Cursor setup)

```javascript
import { createMcpServer } from 'quikdown/mcp';
import QuikdownEditor from 'quikdown/edit';

// A) Cursor / CI / agent on files — headless tool group only
const mcp = createMcpServer();
mcp.listenStdio();

// B) Copilot doc app — headless + editor tool groups
const editor = new QuikdownEditor('#doc', { mode: 'split' });
const mcp = createMcpServer({ editor });
mcp.listenStdio();
// or mcp.handleMessage(req) for WebSocket bridge
```

### Tool inventory

**One server, two groups** — headless always listed; editor group listed when `{ editor }` is passed.  
**No “minimal editor MVP”** — when the editor is bound, expose the full document surface the widget already implements. That is mostly wiring + schemas + tests.

#### Headless group (always)

| Tool | Wires to |
|------|----------|
| `markdown_to_html` | `quikdown(md, options?)` |
| `html_to_markdown` | `quikdown_bd.toMarkdown(html, options?)` |
| `markdown_to_ast` / `markdown_to_json` | structured modules (optional v1) |
| `markdown_stats` | stats helper on string |
| `quikdown_info` | version, modules, active tool groups |

#### Editor group (when `{ editor }` passed) — full power

**Markdown buffer (source of truth):**

| Tool | Wires to |
|------|----------|
| `read_editor` | `editor.getMarkdown()` |
| `write_editor` | `editor.setMarkdown(content)` |
| `find_regex` | regex search on `getMarkdown()` — returns matches (index, line, excerpt, count); **static/safe regex policy** (no dynamic ReDoS patterns from hell) |
| `replace_regex` | regex replace on markdown → `setMarkdown()` — support `limit` (first / all) |
| `replace_text` | literal find/replace first match (keep for simple agent calls) |
| `extract_text` | line range from buffer |
| `get_stats` | stats on buffer |
| `undo` / `redo` | `editor.undo()` / `redo()` |

**HTML / rendered (preview power — what makes quikdown quikdown):**

| Tool | Wires to |
|------|----------|
| `get_html` | `editor.getHTML()` — parser HTML for current buffer (fences, options as editor configured) |
| `get_rendered` | `getRenderedContent(editor.previewPanel, { output })` — **`output`:** `default` \| `stripped` \| `quikdown` (same three profiles as `copyRendered`) — returns rich HTML (+ plain `text` if copy module provides it) for agent inspection / downstream paste |

#### Filesystem group (MCP server only — **not** in core quikdown)

quikdown has **zero file I/O** by design. The **MCP host runs in Node** and owns `fs` — so large documents stay on disk and the LLM reasons about **paths, stats, and excerpts** instead of megabyte tool payloads.

Available when MCP runs in Node (stdio bin, doc host). Optional `createMcpServer({ root?: string })` — default workspace cwd; **reject path traversal** (`..`, absolute outside root).

**Read (avoid stuffing huge strings into agent context):**

| Tool | Purpose |
|------|---------|
| `read_file_info` | `{ path }` → size, line count, mtime — agent decides whether to load |
| `read_file_lines` | `{ path, start_line, end_line }` → excerpt only |
| `read_file_markdown` | `{ path }` → full file (agent opts in explicitly) |
| `load_file_to_editor` | `{ path }` → read file → `editor.setMarkdown()` (editor group only); returns stats, not full body in response if large — configurable threshold |

**Write (filename in args; content from buffer or pipeline — LLM does not pass large bodies):**

| Tool | Purpose |
|------|---------|
| `write_markdown_to_file` | `{ path }` — write **editor buffer** to `.md`; or `{ path, content }` headless when no editor |
| `write_html_to_file` | `{ path }` — write **editor** `getHTML()` to file; headless: `{ path, markdown }` or `{ path, html }` runs pipeline as needed |
| `write_rendered_to_file` | `{ path, output? }` — `output`: `default` \| `stripped` \| `quikdown`; calls `getRenderedContent` → writes rich HTML file (editor / preview required) |

Tool responses: `{ path, bytes_written, lines?, output? }` — not the file contents.

**Why this belongs in MCP:** Cursor agents already edit repo files; quikdown MCP lets them **export quikdown-shaped HTML/rendered** and **roundtrip BD** without pasting 500KB through chat. Core stays browser-safe and zero-deps; **only `quikdown/mcp` imports `fs`**.

**Security (document in `docs/quikdown-mcp.md`):** sandbox to project root; no write outside allowed root unless `allowPaths` opt-in; same trust model as any MCP file tool.

---

### Relationship to existing modules

```
quikdown       → core (headless tools call this)
quikdown/bd    → reverse (headless tools call this)
quikdown/edit  → widget (host creates; optional MCP binding)
quikdown/mcp   → ONE MCP server: headless + filesystem (Node) + editor tools if bound
```

MCP glue is **correlated** with edit/bd/core but **separate export** — like `./bd`. Does not bloat parser or editor bundles unless imported.

**Not quikdown/mcp:** quikchat, bitwrench, finished apps — hosts compose those.

---

### Implementation files (when built)

| File | Role |
|------|------|
| `src/quikdown_mcp_tools_headless.js` | Headless + filesystem read/write helpers (Node `fs`) |
| `src/quikdown_mcp_tools_editor.js` | Editor + regex + HTML/render + export-to-file |
| `src/quikdown_mcp.js` | JSON-RPC server, dynamic `tools/list`, `createMcpServer(options?)` |
| `bin/quikdown-mcp` | CLI entry: stdio, headless-only default |
| Rollup + `package.json` `"./mcp"` | Same pattern as `./bd` |
| `docs/quikdown-mcp.md` | What it is / what you get / Cursor vs embedder |

**Out of MCP package (host UX, not tools):** bundled Cursor↔browser bridge, MCP prompts library.

### High value — consider for 1.2.15+

| Feature | Status | What quikdown does today | Why it matters for LLM/docs |
|---------|--------|--------------------------|----------------------------|
| **Heading slug / `id` attributes** | ❌ | Headings render as `<h1>Title</h1>` with no `id` | Models emit TOC links like `[see above](#installation)` — links go nowhere |

| **4-space indented code blocks** | ❌ | Only fenced ` ``` ` code blocks work | Pasted READMEs and older docs use indentation for code; content becomes plain paragraphs |
| **Nested blockquotes** (`> > quote`) | ❌ | Only single-level `> line` | Quoted LLM output and email-style replies use nested quotes |

| **Link/image title attributes** | 🟡 | Basic `[text](url)` and `![alt](url)` work | `[text](url "hover title")` may not roundtrip through BD — needs contract test |

| Feature | Status | Notes |
|---------|--------|-------|

| Definition lists | ❌ | On `dev/todo.md` under consideration |

- Full CommonMark compliance
- Raw HTML blocks (use fences + `allow_unsafe_html` whitelist)
- Nested blockquotes with **different** markers

## Why test coverage missed these issues

Coverage measures **lines executed in `dist/*.esm.js`**, not **correctness**, **packaging completeness**, or **consumer experience**. Several structural choices let real bugs ship while metrics stayed green.

### 1. Coverage ≠ contract testing

Jest thresholds (100% on core, 58% on editor) only assert that code paths ran. They do not verify:

- npm `exports` / `types` fields resolve to files that exist
- MD → HTML → MD roundtrip preserves semantics (only that code ran)
- Editor security paths under untrusted input
- TypeScript consumers can compile

**Example — table alignment:** `buildTable` runs alignment logic (lines covered ✓) but never writes `data-qd-align`. BD's `walkTable` reads that attribute — but the test in `quikdown_bd_coverage.test.js` **injects HTML with the attribute already present**, so `walkTable` is covered without testing the forward pass contract. **→ Fixed in 1.2.14:** forward emits `data-qd-align`; malformed test strengthened.

**Example — roundtrip test (was weak, now fixed):**

```javascript
// tests/quikdown_malformed.test.js — name says "preserves alignment"
test('tables with alignment -> toMarkdown -> re-parse preserves alignment', () => {
  const markdown = '| Left | Center | Right |\n|:-----|:------:|------:|\n| L | C | R |';
  const html1 = quikdown_bd(markdown);
  expect(html1).toContain('<table');           // weak — no data-qd-align check
  const backToMd = quikdown_bd.toMarkdown(html1);
  expect(backToMd).toContain('|');             // weak — any table markdown
  // never asserts |:---|, |:---:|, |---:| in backToMd
});
```

100% line coverage on both modules; alignment bug undetected.

### 2. Tests target `dist/`, CI runs test before build

`collectCoverageFrom` lists only `dist/*.esm.js`. Tests `import` from `dist/`. ~~CI runs `npm test` then `npm run build`.~~ **→ Fixed in 1.2.14:** CI runs build → test. Husky pre-commit still lint + test only (no forced rebuild).

`npm run release` now runs build → test.

### 3. Split ownership: write path vs read path

Bidirectional bugs hide when forward and reverse are tested in isolation:

| Path | Test style | Gap |
|------|------------|-----|
| Forward (`quikdown.js`) | HTML output contains `<table>`, `text-align` | ~~No `data-qd-align` assertion~~ → fixed 1.2.14 |
| Reverse (`quikdown_bd.js`) | Synthetic HTML with attrs hand-built | Never proves parser emitted them |

Need **integration tests** that roundtrip real parser output, not fixture HTML.

### 4. Coverage boosters optimize the metric, not behavior

Files like `quikdown_100pct.test.js`, `*_coverage.test.js` target dist line numbers and `istanbul ignore` branches. They inflate the ~99% badge without adding consumer-facing assertions. The README badge reflects **execution**, not **quality**.

### 5. Out-of-band artifacts never gated

TypeScript `.d.ts` files are declared in `package.json` but:

- Not in `collectCoverageFrom` (not JS)
- Not in CI `test -f` checklist (only `.js` bundles checked)
- Not verified by `npm pack --dry-run`
- Not in `publish.yml` release asset list
- `tools/release.sh` runs test + build but never validates types

They were marked done in `dev/todo_completed.md` but can drift out of repo without any gate failing. **→ Partially fixed:** `.d.ts` restored; `verifyPackage.cjs` + CI file checks; `npm pack` audit still TODO.

### 6. Editor and e2e explicitly de-prioritized

Editor threshold ~49% lines. Playwright specs exist; **→ Partially fixed:** e2e job in CI with `continue-on-error: true`. Security paths still need DOM/integration tests.

### 7. Documentation not tested

`allow_unsafe_html` in code + release notes but absent from `api-reference.md` — no test compares docs to exported options. Doc drift is invisible to Jest. **→ Fixed in 1.2.14:** api-reference + security whitelist section.

## Contract testing guide

Contract tests: **Does A produce what B expects?** Not: did line 742 run?

### Anti-pattern vs pattern

```javascript
// BAD — reverse only, hand-built HTML
const html = `<table data-qd-align="left,center,right">...</table>`;
expect(quikdown_bd.toMarkdown(html)).toContain('|:---:|');

// GOOD — full pipeline
const md = '| L | C | R |\n|:--|:--:|--:|\n| a | b | c |';
const html = quikdown_bd(md);
expect(html).toMatch(/data-qd-align="left,center,right"/);
```

### Contract types

| Boundary | Owner | Invariant |
|----------|-------|-----------|
| Package ↔ consumer | `verifyPackage.cjs` + Jest mirror | Every `exports.types` exists |
| Parser → BD | `quikdown_bd_contract.test.js` | `data-qd*` on real parser output roundtrips |
| Classifier ↔ parser ↔ editor | `quikdown_classify_agreement.test.js` | Same line → same block type |
| AST ↔ HTML | `quikdown_ast_contract.test.js` | Same structure as direct parse |
| Editor ↔ parser options | edit contract / Playwright | `allowUnsafeHTML` maps correctly |
| Security | `xss-payloads.js` | Untrusted paths blocked |

## Planning for MCP — user journeys

Companion to [MCP plan for quikdown](#mcp-plan-for-quikdown) (architecture and tool inventory). This section answers: **what does a user actually do to get a good MCP + LLM experience?**

**Reminder:** One package (`quikdown/mcp`), one server, two tool groups. Setup differs by audience — not by installing two different MCP products.

---

### Two audiences, same MCP

| User type | What they want | What they set up |
|-----------|----------------|------------------|
| **Developer in Cursor / Claude Code** | Agent safely parses and converts markdown in the repo | MCP config + `quikdown-mcp` bin (headless tool group only) |
| **Embedder / copilot doc product** | Agent edits a live doc; human sees quikdown preview | Host app with `QuikdownEditor` + `createMcpServer({ editor })` |

Lead docs with **Path A** (low friction). Path B is the product differentiator for embedders.

---

### Path A — Cursor / Claude Code on repo markdown (headless)

**Goal:** “When I work on `README.md` with the agent, use quikdown for safe HTML, BD roundtrip, stats — not guesswork.”

**User steps:**

1. Install quikdown (project or global): `npm install quikdown` (or use `npx` when `quikdown-mcp` bin ships).
2. Add MCP to the LLM host — e.g. Cursor Settings → MCP:
   ```json
   {
     "quikdown": {
       "command": "npx",
       "args": ["quikdown-mcp"]
     }
   }
   ```
   Starts headless server on stdio. No editor, no extra app window.
3. Use the agent on `.md` files. Model sees headless tools (`markdown_to_html`, `html_to_markdown`, `markdown_stats`, `quikdown_info`, …) and calls them when relevant.
4. **Optional:** Project hint in `AGENTS.md` or `.cursor/rules`: “Use quikdown MCP for markdown/HTML conversion; default safe parse.”

**Experience:**

- User still edits in **Cursor’s (or Claude Code’s) editor**.
- Agent converts snippets, checks BD roundtrip, validates HTML before suggesting patches.
- Strong fit: doc refactors, HTML→MD migration, fence-heavy content checks.

**Does not include (set expectations):**

- QuikdownEditor split view inside Cursor
- Live Mermaid/math preview via MCP
- Agent driving a quikdown preview pane → that is Path B

**Ship to make Path A feel good:**

- Clear tool descriptions; `quikdown_info` documents options and safe defaults
- Short doc: “Cursor MCP setup in 60 seconds”
- Sensible defaults (XSS-safe parse; BD for reverse)

---

### Path B — Copilot doc app (editor + MCP)

**Goal:** “Human watches rendered markdown update while the agent rewrites the document.”

**User steps:**

1. Run (or build) a **host** that includes:
   - `QuikdownEditor` on screen (split or preview)
   - `createMcpServer({ editor })` in the same process (Electron, Tauri, or Node + WebSocket bridge)
2. Point the LLM host at that MCP server — same MCP config pattern, but command starts the **host**, not bare headless bin:
   ```json
   {
     "quikdown": {
       "command": "node",
       "args": ["./my-doc-app/start-mcp.js"]
     }
   }
   ```
3. Open the doc app; use Cursor or Claude Code beside it. Agent calls `read_editor` / `write_editor`; preview updates in the app.

**Experience:**

- **Human:** QuikdownEditor — fences, math, diagrams, rich copy.
- **Agent:** Editor tool group on the live buffer (plus headless tools if host exposes both).
- Optional: quikchat in the app for chat; MCP for Cursor as a second agent client.

**User must accept:**

- Doc app must be **running** before editor MCP tools work.
- Often two surfaces: agent client + doc app (unless host merges layout).
- MCP does **not** turn Cursor’s file pane into QuikdownEditor.

**Ship to make Path B feel good:**

- One action: “Start doc session” (editor + MCP)
- Tool-call log in UI (“agent replaced lines 10–20”)
- Example host: extend `llm-tool-editor` or minimal Electron sample

---

### Path C — Power user (both)

Same person may use:

- **Headless MCP in Cursor** for day-to-day repo `.md` work
- **Editor-bound MCP** when drafting a long artifact in a doc app or try-it + local bridge

One package; choice is **which host is running**, not which quikdown MCP to install.

---

### “Nice experience” checklist

| | **Path A — Headless** | **Path B — Editor session** |
|--|----------------------|----------------------------|
| User installs | npm + MCP config block | Host app or documented example |
| User runs daily | Nothing extra | Doc app must be up |
| Human UI | IDE file editor | QuikdownEditor preview |
| Agent UI | Cursor / Claude Code | Same |
| Preview quality | IDE preview (if any) | Full quikdown fence catalog |
| Typical setup time | ~2 minutes | Higher unless we ship a ready-made host |
| Primary doc to write first | **Yes** | Embedder guide + example |
