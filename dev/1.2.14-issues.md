## Why test coverage missed these issues

Coverage measures **lines executed in `dist/*.esm.js`**, not **correctness**, **packaging completeness**, or **consumer experience**. Several structural choices let real bugs ship while metrics stayed green.

### 1. Coverage ≠ contract testing

Jest thresholds (100% on core, 49% on editor) only assert that code paths ran. They do not verify:

- npm `exports` / `types` fields resolve to files that exist
- MD → HTML → MD roundtrip preserves semantics (only that code ran)
- Editor security paths under untrusted input
- TypeScript consumers can compile

**Example — table alignment:** `buildTable` runs alignment logic (lines covered ✓) but never writes `data-qd-align`. BD's `walkTable` reads that attribute — but the test in `quikdown_bd_coverage.test.js` **injects HTML with the attribute already present**, so `walkTable` is covered without testing the forward pass contract.

**Example — roundtrip test name vs assertion:**

```javascript
// tests/quikdown_malformed.test.js — name says "preserves alignment"
test('tables with alignment -> toMarkdown -> re-parse preserves alignment', () => {
  const markdown = '| Left | Center | Right |\n|:-----|:------:|------:|\n| L | C | R |';
  const html1 = quikdown_bd(markdown);
  expect(html1).toContain('<table');           // weak — no data-qd-align check
  const backToMd = quikdown_bd.toMarkdown(html1);
  expect(backToMd).toContain('|');             // weak — any table markdown
  // never asserts |:---|, |:---:|, |---:| in backToMd
});
```

100% line coverage on both modules; alignment bug undetected.

### 2. Tests target `dist/`, CI runs test before build

`collectCoverageFrom` lists only `dist/*.esm.js`. Tests `import` from `dist/`. CI runs `npm test` then `npm run build`. A PR can change `src/` only, pass against **stale committed dist**, and merge. Coverage reports green execution of **old** code.

`npm run release` runs test-then-build too (same ordering), but at least rebuilds before merge — **CI PR checks do not**.

### 3. Split ownership: write path vs read path

Bidirectional bugs hide when forward and reverse are tested in isolation:

| Path | Test style | Gap |
|------|------------|-----|
| Forward (`quikdown.js`) | HTML output contains `<table>`, `text-align` | No `data-qd-align` assertion |
| Reverse (`quikdown_bd.js`) | Synthetic HTML with attrs hand-built | Never proves parser emitted them |

Need **integration tests** that roundtrip real parser output, not fixture HTML.

### 4. Coverage boosters optimize the metric, not behavior

Files like `quikdown_100pct.test.js`, `*_coverage.test.js` target dist line numbers and `istanbul ignore` branches. They inflate the ~99% badge without adding consumer-facing assertions. The README badge reflects **execution**, not **quality**.

### 5. Out-of-band artifacts never gated

TypeScript `.d.ts` files are declared in `package.json` but:

- Not in `collectCoverageFrom` (not JS)
- Not in CI `test -f` checklist (only `.js` bundles checked)
- Not verified by `npm pack --dry-run`
- Not in `publish.yml` release asset list
- `tools/release.sh` runs test + build but never validates types

They were marked done in `dev/todo_completed.md` but can drift out of repo without any gate failing.

### 6. Editor and e2e explicitly de-prioritized

Editor threshold ~49% lines. Playwright specs exist but **not in CI**. Security issues (lang attr injection, copy re-sanitization, contenteditable paste) need DOM/integration tests — unit coverage of dist lines won't catch them.

### 7. Documentation not tested

`allow_unsafe_html` in code + release notes but absent from `api-reference.md` — no test compares docs to exported options. Doc drift is invisible to Jest.

## P1 — Bidirectional & Parser Fidelity

### [ ] Restore `data-qd-align` emission in `buildTable`

**Problem:** `buildTable` in `src/quikdown.js` parses column alignment (`:---`, `:---:`, `---:`) and applies `text-align` inline styles, but **never writes `data-qd-align`**. `quikdown_bd.js` reads `data-qd-align` when reconstructing markdown tables. The old logic still exists in `exp-bd/`.

**Impact:** Table alignment is lost on MD → HTML → MD roundtrip.

**Files:** `src/quikdown.js` (`buildTable`, ~741–800), `src/quikdown_bd.js`, `tests/quikdown_bd.test.js`, `tests/quikdown_malformed.test.js`

**Suggested fix:** Emit `data-qd-align="left,center,right"` on `<table>` (and optionally per-cell attrs) when `bidirectional: true`, matching `exp-bd/src/quikdown_bd.js` pattern.

**Suggested test cases:**

```javascript
import quikdown_bd from '../dist/quikdown_bd.esm.js';

const md = [
  '| L | C | R |',
  '|---|---|---|',
  '| a | b | c |',
].join('\n').replace('|---|', '|:--|:--:|--:|');

const html = quikdown_bd(md);
expect(html).toMatch(/data-qd-align="left,center,right"/);

const roundtripped = quikdown_bd.toMarkdown(html);
expect(roundtripped).toMatch(/\|:--\|/);   // left
expect(roundtripped).toMatch(/\|:--:\|/);  // center
expect(roundtripped).toMatch(/\|--:\|/);   // right
```

```markdown
| Left | Center | Right |
|:-----|:------:|------:|
| a    | b      | c     |
```

Expected roundtrip separator row preserves `:---`, `:---:`, `---:` per column.

**Files:** `src/quikdown_edit.js` (~1153), optionally `src/quikdown.js` (~534, `class="language-${lang}"`)

## QA strategy

Condensed testing methodology for quikdown. Goal: **confidence layers** — coverage is the floor; contracts, consumers, and e2e are the ceiling.

### Test pyramid (confidence layers)

```
                    ┌─────────────────────┐
                    │  Consumer QA        │  verifyPackage, npm pack, tsc fixture
                    ├─────────────────────┤
                    │  E2E (Playwright)   │  editor, fences, paste, whitelist HTML
                    ├─────────────────────┤
                    │  Contract tests     │  parser↔BD, classify↔parser, AST↔HTML
                    ├─────────────────────┤
                    │  Fixture matrix     │  markdown-samples + bidirectional-contracts
                    ├─────────────────────┤
                    │  Property / fuzz    │  roundtrip invariants, XSS corpus (optional)
                    ├─────────────────────┤
                    │  Unit (behavior)    │  one concern per test; fresh dist in CI
                    └─────────────────────┘
```

**Rule:** No layer replaces another. 100% line coverage on `dist/quikdown.esm.js` does not substitute for [`verifyPackage.cjs`](../tools/verifyPackage.cjs) or contract tests.

Recommended CI order: **build → verify:package → test → e2e smoke**.

## Contract testing guide

Contract tests assert **agreements between modules or between code and packaging metadata**. They answer: *"Does A produce what B expects?"* — not *"Did line 742 execute?"*

### Why quikdown needs them

| Bug found in review | Unit coverage | Contract test would |
|---------------------|---------------|---------------------|
| Missing `dist/*.d.ts` | N/A (not JS) | `verifyPackage` + package contract test |
| Table alignment roundtrip | 100% on forward + reverse | Fail: no `data-qd-align` in parser HTML |
| HR parser vs classifier drift | Both modules covered | Fail: `isHRLine('***')` ≠ parser output |
| Weak roundtrip assertion | Test passed | Fail: `backToMd` missing `\|:--:\|` |

### Contract types for this codebase

#### 1. Package ↔ consumer contracts

**Owner:** [`tools/verifyPackage.cjs`](../tools/verifyPackage.cjs) (CI/release) + `tests/quikdown_package_contract.test.js` (Jest duplicate for local dev).

**Invariant:** Every path in `package.json` `exports` and `types` resolves to a file that exists after build.

**Also TODO:** `tests/fixtures/ts-consumer/` — minimal TS project importing all subpaths; `npm run verify:types`.

#### 2. Parser forward ↔ BD reverse contracts

**Owner:** `tests/quikdown_bd_contract.test.js` + `tests/fixtures/bidirectional-contracts.js`.

**Pattern — always start from real parser output, never hand-built HTML:**

```javascript
import quikdown_bd from '../dist/quikdown_bd.esm.js';

function assertBidirectionalContract(md, { htmlPatterns = [], mdPatterns = [] }) {
  const html = quikdown_bd(md);                    // forward WITH bidirectional: true
  for (const p of htmlPatterns) expect(html).toMatch(p);

  const back = quikdown_bd.toMarkdown(html);       // reverse
  for (const p of mdPatterns) expect(back).toMatch(p);

  const html2 = quikdown_bd(back);                 // re-forward stability
  expect(html2).toMatch(/<table|<h1|<ul|<pre/);    // feature-specific
}
```

**Contracts to implement (checklist):**

- [ ] **Tables:** `data-qd-align` in HTML; separator row `:---`, `:---:`, `---:` in `back`
- [ ] **Headings:** `data-qd="###"` (or equivalent) roundtrips to same heading level
- [ ] **Fences:** `data-qd-source`, `data-qd-lang` present; language preserved on roundtrip
- [ ] **Links / images:** `data-qd` on anchors; href and alt survive
- [ ] **Lists:** task list checkbox syntax; nested indent stable within 2-space rule
- [ ] **Blockquotes:** `data-qd` emitted (when implemented) — until then, document as known gap
- [ ] **HR:** parser and classifier agree on which lines produce `<hr>`

**Anti-pattern to avoid** (current state in `quikdown_bd_coverage.test.js`):

```javascript
// BAD: tests reverse in isolation — forward contract never verified
const html = `<table data-qd-align="left,center,right">...</table>`;
expect(quikdown_bd.toMarkdown(html)).toContain('|:---:|');
```

```javascript
// GOOD: full pipeline from markdown
const md = '| L | C | R |\n|:--|:--:|--:|\n| a | b | c |';
const html = quikdown_bd(md);
expect(html).toMatch(/data-qd-align="left,center,right"/);
```

#### 3. Classifier ↔ parser ↔ editor contracts

**Owner:** extend [`tests/quikdown_classify_agreement.test.js`](../tests/quikdown_classify_agreement.test.js).

**Invariant:** For each line type (HR, fence open/close, list item, table row), `classifyLine()` prediction matches what parser and editor preview do.

```javascript
const LINE_CASES = [
  { line: '---', expectHR: true,  parserHR: true  },
  { line: '***', expectHR: true,  parserHR: false }, // document decision
  { line: '| a | b |', expectTable: true },
];

for (const { line, ...expected } of LINE_CASES) {
  test(`classify agreement: ${JSON.stringify(line)}`, () => {
    const classified = classifyLine(line);
    const parserHtml = quikdown(line + '\n');
    // assert classified.type matches parserHtml structure
  });
}
```

#### 4. AST ↔ HTML parity contracts

**Owner:** `tests/quikdown_ast_contract.test.js`.

**Invariant:** Structured output matches direct HTML for the same markdown (structure, not necessarily identical class names).

```javascript
const md = '# Title\n\n**bold** and [link](https://example.com)';
const ast = quikdown_ast(md);
const htmlFromAst = quikdown_ast_html(ast);
const htmlDirect = quikdown(md);
// Both contain h1, strong, a[href] — use DOMParser or regex bundles
```

#### 5. Editor ↔ parser option contracts

**Owner:** `tests/quikdown_edit_contract.test.js` or Playwright `@smoke`.

**Invariant:** Editor options map correctly to parser options (`allowUnsafeHTML` → `allow_unsafe_html`, `lazy_linefeeds`, etc.).

```javascript
editor.setMarkdown('<div>x</div>');
editor.cycleAllowUnsafeHTML(); // → 'limited'
expect(editor.getHTML()).toMatch(/<div/);
expect(editor.getHTML()).not.toMatch(/<script/);
```

#### 6. Security / trust-boundary contracts

**Owner:** `tests/quikdown_security.test.js` + Playwright paste/copy scenarios.

| Surface | Input trust | Contract |
|---------|-------------|----------|
| Default parser | Untrusted | No `<script`, no `javascript:` href |
| `allow_unsafe_html: true` | Trusted only | Documented; no auto-test bypass |
| Editor contenteditable paste | Untrusted | Preview HTML safe after paste |
| `customFences` | Trusted dev | Documented |
| Rich copy output | Untrusted recipient | Clipboard HTML has no `onerror=` |

### How to add a new contract test (workflow)

1. **Identify the boundary** — which module writes, which reads? (e.g. `buildTable` writes, `walkTable` reads)
2. **Write the invariant** in plain English — *"Aligned tables emit `data-qd-align` matching separator row"*
3. **Add fixture** to `tests/fixtures/bidirectional-contracts.js` with `htmlMustContain` / `roundtrip.mdMustMatch`
4. **Implement test** using real `quikdown_bd(md)` — not synthetic HTML unless testing reverse-only edge case
5. **Name test for the contract** — `contract: table alignment forward emits data-qd-align`
6. **Do not chase line coverage** — one contract test beats ten coverage-booster lines

### Contract vs coverage: when to use which

| Question | Use |
|----------|-----|
| Did this branch execute? | Coverage (existing Jest) |
| Does npm tarball include types? | `verifyPackage.cjs` |
| Does parser output work with BD? | Contract test |
| Does pasted HTML XSS preview? | Playwright + security corpus |
| Would a one-line bug be caught? | Mutation testing (optional) |
