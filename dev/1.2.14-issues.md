## Why test coverage missed these issues

Coverage measures **lines executed in `dist/*.esm.js`**, not **correctness**, **packaging completeness**, or **consumer experience**. Several structural choices let real bugs ship while metrics stayed green.

### 1. Coverage ≠ contract testing

Jest thresholds (100% on core, 58% on editor) only assert that code paths ran. They do not verify:

- npm `exports` / `types` fields resolve to files that exist
- MD → HTML → MD roundtrip preserves semantics (only that code ran)
- Editor security paths under untrusted input
- TypeScript consumers can compile

**Example — table alignment:** `buildTable` runs alignment logic (lines covered ✓) but never writes `data-qd-align`. BD's `walkTable` reads that attribute — but the test in `quikdown_bd_coverage.test.js` **injects HTML with the attribute already present**, so `walkTable` is covered without testing the forward pass contract. **→ Fixed in 1.2.14:** forward emits `data-qd-align`; malformed test strengthened.

**Example — roundtrip test (was weak, now fixed):**

```javascript
// tests/quikdown_malformed.test.js — name says "preserves alignment"
test('tables with alignment -> toMarkdown -> re-parse preserves alignment', () => {
  const markdown = '| Left | Center | Right |\n|:-----|:------:|------:|\n| L | C | R |';
  const html1 = quikdown_bd(markdown);
  expect(html1).toContain('<table');           // weak — no data-qd-align check
  const backToMd = quikdown_bd.toMarkdown(html1);
  expect(backToMd).toContain('|');             // weak — any table markdown
  // never asserts |:---|, |:---:|, |---:| in backToMd
});
```

100% line coverage on both modules; alignment bug undetected.

### 2. Tests target `dist/`, CI runs test before build

`collectCoverageFrom` lists only `dist/*.esm.js`. Tests `import` from `dist/`. ~~CI runs `npm test` then `npm run build`.~~ **→ Fixed in 1.2.14:** CI runs build → test. Husky pre-commit still lint + test only (no forced rebuild).

`npm run release` now runs build → test.

### 3. Split ownership: write path vs read path

Bidirectional bugs hide when forward and reverse are tested in isolation:

| Path | Test style | Gap |
|------|------------|-----|
| Forward (`quikdown.js`) | HTML output contains `<table>`, `text-align` | ~~No `data-qd-align` assertion~~ → fixed 1.2.14 |
| Reverse (`quikdown_bd.js`) | Synthetic HTML with attrs hand-built | Never proves parser emitted them |

Need **integration tests** that roundtrip real parser output, not fixture HTML.

### 4. Coverage boosters optimize the metric, not behavior

Files like `quikdown_100pct.test.js`, `*_coverage.test.js` target dist line numbers and `istanbul ignore` branches. They inflate the ~99% badge without adding consumer-facing assertions. The README badge reflects **execution**, not **quality**.

### 5. Out-of-band artifacts never gated

TypeScript `.d.ts` files are declared in `package.json` but:

- Not in `collectCoverageFrom` (not JS)
- Not in CI `test -f` checklist (only `.js` bundles checked)
- Not verified by `npm pack --dry-run`
- Not in `publish.yml` release asset list
- `tools/release.sh` runs test + build but never validates types

They were marked done in `dev/todo_completed.md` but can drift out of repo without any gate failing. **→ Partially fixed:** `.d.ts` restored; `verifyPackage.cjs` + CI file checks; `npm pack` audit still TODO.

### 6. Editor and e2e explicitly de-prioritized

Editor threshold ~49% lines. Playwright specs exist; **→ Partially fixed:** e2e job in CI with `continue-on-error: true`. Security paths still need DOM/integration tests.

### 7. Documentation not tested

`allow_unsafe_html` in code + release notes but absent from `api-reference.md` — no test compares docs to exported options. Doc drift is invisible to Jest. **→ Fixed in 1.2.14:** api-reference + security whitelist section.

## Contract testing guide

Contract tests: **Does A produce what B expects?** Not: did line 742 run?

### Anti-pattern vs pattern

```javascript
// BAD — reverse only, hand-built HTML
const html = `<table data-qd-align="left,center,right">...</table>`;
expect(quikdown_bd.toMarkdown(html)).toContain('|:---:|');

// GOOD — full pipeline
const md = '| L | C | R |\n|:--|:--:|--:|\n| a | b | c |';
const html = quikdown_bd(md);
expect(html).toMatch(/data-qd-align="left,center,right"/);
```

### Contract types

| Boundary | Owner | Invariant |
|----------|-------|-----------|
| Package ↔ consumer | `verifyPackage.cjs` + Jest mirror | Every `exports.types` exists |
| Parser → BD | `quikdown_bd_contract.test.js` | `data-qd*` on real parser output roundtrips |
| Classifier ↔ parser ↔ editor | `quikdown_classify_agreement.test.js` | Same line → same block type |
| AST ↔ HTML | `quikdown_ast_contract.test.js` | Same structure as direct parse |
| Editor ↔ parser options | edit contract / Playwright | `allowUnsafeHTML` maps correctly |
| Security | `xss-payloads.js` | Untrusted paths blocked |

- [x] **Tables:** `data-qd-align` + separator row (1.2.14)
- [x] **Headings:** `data-qd` roundtrips level (tested via editor roundtrip)
- [ ] **Fences:** each built-in lang — render + BD where applicable
- [x] **Links / images:** href, alt survive (tested via editor roundtrip)
- [x] **Lists / task lists:** checkbox syntax (tested via editor roundtrip)
- [x] **Blockquotes:** `data-qd` emitted (forward + roundtrip contract tests)
- [ ] **HR:** parser vs classifier policy decided

|------|---------|
